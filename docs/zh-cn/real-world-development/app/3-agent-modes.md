我们先为项目添加了一项小功能，但较大的更改需要更完善的流程。GitHub Copilot app 支持组织现有的工作方式，帮助我们用正确的方法构建所需功能。从本课开始，你将通过几节课遵循典型的智能体驱动开发流程：从议题实现新功能，确保代码有效且功能行为符合预期，最后将其成功合并到项目中。

> [!NOTE]
> 后续功能工作流会继续使用同一个会话。通常，不同类型的文件会使用不同会话或 PR；本工作坊为专注于核心概念而简化了流程。

本课将学习：

- 从 GitHub 议题启动新的智能体会话。
- 在 **Plan** 模式中明确需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

之后还会更新存储库指令、自定义现有的 `quality-checks` 技能、添加 MCP 验证、创建 QA 智能体并创建功能 PR。

## 场景

Tailspin Toys 的目录不断扩大，访问者需要按类别和发行商筛选游戏。待办议题描述了功能，但在编码前还要商定多个类别如何组合等细节。你将使用 Plan 模式明确这些决定，再授权 Autopilot 在范围明确的前提下实现功能。

## 背景

在开发流程中引入 AI 编码智能体并不会改变基本原则，反而让这些原则更加重要。大多数开发人员的流程大致如下：

1. 打开详细说明待完成工作的议题。
2. 制定构建方案。
3. 编写并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求 (PR)。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程会因团队和组织而异，但大多数流程都与上述步骤类似。

遵循标准流程，可确保 AI 生成的代码符合需求，并经过与手写代码相同的审查流程。

## 会话模式

**会话模式**决定智能体的自主程度。可以在提示词字段下方的下拉菜单中设置模式，并随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你的输入后再继续。
- **Plan**：智能体先制定计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主工作，包括编写代码、运行测试和迭代，无需等待输入。

先在 Plan 模式中审查计划，再切换到 Autopilot 实现。

## 从议题启动会话

开始前，确认星级评分 PR 已合并，并且本地 `main` 已更新。

1. 在侧边栏 **Sessions** 下选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是预先创建的议题，无需再创建。
2. 选择 **New session**，然后选择基于更新后 `main` 的**新工作树**。

    ![GitHub Copilot app 的议题视图中箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果命令在终端中可用，但会话中不可用，请检查应用的 PATH 或版本管理器配置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装它。

## 规划筛选功能

规划让你能在 Copilot 编写代码前审查方案。由于会话从议题启动，Copilot 已获得功能请求的上下文。发送：

```plaintext
Build this feature.
```

回答 Copilot 的问题，并对照议题验收标准审查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问更改和测试。讨论不明确的行为，例如多个类别如何组合，或没有游戏匹配时如何处理。

计划应使用项目现有工具运行 lint、单元测试、E2E 测试和类型检查。将范围限定为筛选功能的实现和测试；完成质量工作流后再创建 PR。批准前先要求修改不符合预期的计划，并保留议题 URL 和已商定的澄清内容，供后续验证使用。

## 明确批准 Autopilot

对计划满意后，选择 **Approve and implement this plan**，或当前版本中含义相同的选项。不要假设批准计划会自动切换模式；请确认当前模式指示器显示 **Autopilot**。

Copilot 会按照计划实现功能、生成代码并运行测试。

> [!NOTE]
> 批准后可能立即开始实现，因此务必先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，应先解决环境问题，再判断检查是否完成。只停止自己启动的服务器。

## 审查并验证实现

与其他代码一样，生成的代码也需要在合并前审查：

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 对照议题和已批准的澄清内容检查结果，包括类别和发行商组合，并确认更改遵循存储库指令。
3. 查看 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不算通过。
4. 接受实现前解决失败项并重新运行受影响的检查。Playwright E2E 配置会构建并提供预览服务器，也可能复用本地服务器；确保正在测试的是此工作树的服务器，而不是上一课的服务器。

## 探索新功能

代码看起来没问题，还需要确认它能否运行。像之前一样启动应用，并在浏览器画布中打开网站：

1. 使用以下提示词，让 Copilot 启动应用并在浏览器画布中打开页面：

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. 稍等片刻，应用会启动，Copilot app 内会打开浏览器窗口。
3. 选择一个类别，确认结果符合该类别。清除筛选，再选择发行商，确认结果符合该发行商。
4. 组合类别和发行商筛选，并根据议题和已批准的计划检查结果。如果支持多个类别，也要验证已商定的组合方式。
5. 测试没有匹配游戏的筛选组合，检查空状态。清除或重置筛选，确认完整列表恢复。
6. 完成后，使用以下提示词让 Copilot 停止为此会话启动的开发服务器并关闭浏览器画布：

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 为后续课程保留此会话

暂时不要创建或合并筛选功能 PR。请保留此会话、工作树和分支，供第 4 至第 8 课使用。接下来会将自定义指令应用于筛选代码，再添加技能和 QA 改进，最后在第 8 课创建并合并组合 PR。停止开发服务器后，可以让会话保持空闲，并在下一课继续使用。

## 总结与后续步骤

你已使用不同智能体模式构建并审查功能。本课中，你从 GitHub 议题启动新的智能体会话，在 **Plan** 模式中明确需求，使用 **Autopilot** 实现功能，审查了代码，并在浏览器画布中手动验证。
